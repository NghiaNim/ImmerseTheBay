# Phone practice and MR handoff

Use the development app (`com.immersethebay.app`) on Galaxy S25 with Air 2 Ultra. Keep the installed official XREAL SDK 3.1 demo and its source as the known-good reference; do not change its rig, scene, or APK. The development APK has one phone launcher entry. The phone homepage works without glasses.

## Set up the environment

- Mac: install Node.js 20 or newer (verified with 25.2.1), Android platform-tools (`adb`), and Unity **6000.0.85f2** via Unity Hub with Android Build Support, SDK/NDK Tools, and OpenJDK.
- Clone ImmerseTheBay and check out `main`. Under ignored `Builds/`, prepare **two separate copies** of [XREALSDKTemplate 3.1](https://github.com/dengxian-xreal/XREALSDKTemplate/releases/tag/3.1.0) (commit `91806e6`): one untouched reference and one development checkout called `helloMR-baseline`. Open only the development checkout in Unity 6000.0.85f2. In that checkout, use XRI 2.6.5 and AR Foundation 6.0.7; import the separately obtained XREAL 3.1 tarball at the dev project root with the UPM reference `file:../com.xreal.xr.tar.gz`. Import the XRI Starter Assets sample so the build tool can find `Assets/Samples/XR Interaction Toolkit/2.6.5/Starter Assets/DemoScene.unity`. Enable Custom Main Gradle Template and Android Internet Access; allow HTTP for the LAN dev Portal. Close the Unity GUI before the batch build.
- In `portal/`, copy [`.env.example`](../../portal/.env.example) to the ignored `.env` on a fresh setup. Set `REACTOR_API_KEY` for video, `OPENAI_API_KEY` with project access to `gpt-6-luna` for photo practice and branching, and `CARTESIA_API_KEY` / `CARTESIA_VOICE_ID` for speech. Live **Talk** also requires `CARTESIA_AGENT_ID` for the managed agent in the same Cartesia project. See [Cartesia setup](IMPLEMENTATION-conversational-agent.md). Keep all provider keys out of Unity, screenshots, and Git.
- Keep Mac and S25 on the same reachable Wi-Fi. In the isolated dev project's ignored `Assets/StreamingAssets/visko.json`, use `{"portalUrl":"http://<mac-lan-ip>:8793","portalToken":"","model":"dynamic","autoJoin":false}`. If you set `PORTAL_TOKEN` in Portal, enter the same value in `portalToken`. Use the Mac LAN address rather than localhost in the APK. Restart/rebuild when the development LAN address changes.
- Install the existing XREAL ControlGlasses runtime on S25 and use Samsung's **Connected display → Mirrored** setting for glasses. Pair Android Wireless debugging once with `adb pair <ip>:<pairing-port>`; then use `adb connect <ip>:<connection-port>` from the main Wireless debugging screen. Verify with `adb devices`. Use the stable XREAL 3.1 reference app to distinguish headset/runtime failures from app regressions. See the [device notes](IMPLEMENTATION-s25-phone-practice.md) for the S25-specific runtime workaround already in use on this device.

## Run the demo

1. In one terminal, run `cd portal && npm ci && PORT=8793 node server.js`. Check `curl -fsS http://localhost:8793/api/health`. The browser demo is at `http://localhost:8793/learn.html`.
2. From the repo root, run `tools/android-dev/stage.sh`, then `/Applications/Unity/Hub/Editor/6000.0.85f2/Unity.app/Contents/MacOS/Unity -batchmode -nographics -projectPath "$PWD/Builds/helloMR-baseline" -buildTarget Android -executeMethod DevReferenceBuild.Build -logFile /tmp/itb-android-build.log`. Confirm `XRI_DEV_BUILD_RESULT=Succeeded ERRORS=0`. Install `Builds/official-hellomr/ImmerseTheBay-XRI-live-dev.apk` with `adb install --no-incremental -r`. Use `adb shell am start -n com.immersethebay.app/com.immersethebay.phone.PhonePracticeActivity` to open the phone homepage. See [dev build notes](../../tools/android-dev/README.md).
3. Open **ImmerseTheBay Dev**. Select **Convenience-store Shopping**, **An Afternoon at Home**, or an unexpired photo practice. To make one, open the phone camera, take and confirm the photo, preview it, type or dictate a goal, and tap **Upload and create practice**. The generated session is selected automatically. Up to five recent photo sessions stay in app memory; the Portal expires them within 30 minutes. A process restart clears the phone list.
4. With the glasses connected, tap **Open selected session in glasses** on the phone, then **Start session** on the XREAL controller. **Choose session** returns to the phone picker. The selected preset uses its bundled image; a photo lesson sends its original JPEG to Reactor as the starting image.

The dev build hides sample scenery. The video is a feathered overlay with horizontal head following and fades as you look down. Subtitle and control panels are separate. **Place controls** on the phone raycasts at a nearby upward horizontal plane; it requires a detected surface. The first store lesson highlights vocabulary such as おにぎり. Cartesia handles the clerk voice separately from the generated video track.

## Android signing on a shared device

Each developer can build and install on a fresh device with a locally generated debug keystore. To update an existing `com.immersethebay.app` installation with `adb install -r`, use an APK signed with the same certificate as the installed build. A different debug key causes `INSTALL_FAILED_UPDATE_INCOMPATIBLE`. Compare the APK certificate fingerprints with `apksigner verify --print-certs <apk>`.

For an in-place update on the shared S25, use an APK signed by the current build owner. For ongoing team builds, use a dedicated development signing key in a team secret manager or a signing job. Keep private keystores out of Git. If the existing S25 build can be discarded, back up any needed app data and uninstall `com.immersethebay.app` before installing a build signed with a different key. Uninstalling deletes that app's local data.

## Evidence and next steps

- Portal: 183 tests passed, including a regression that supplies an oversized model response and verifies a single bounded retry. A real JPEG request with a Chinese goal generated three lines and returned the original photo over HTTP 200. The retry covers invalid model output; provider outages can still return an error.
- S25: Android reported exactly one ordinary launcher activity. The session-picker APK built with zero errors, installed, and displayed both presets on S25. Verify the Unity handoff on hardware, especially switching photo → preset so neither the photo nor its lesson is reused.
- Hardware acceptance: use the S25 rear camera for a fresh photo with an actual goal, start it in glasses, and confirm the photo is the scene seed. Run both preset choices as well. Listen to the generated video in a quiet moment before the clerk speaks; its prompt asks for ambience only, but a prompt cannot guarantee zero speech. If voices persist, add a generated-track mute control that leaves Cartesia intact.
- Test optical see-through in a real room: look down and up to check the video fade and recovery; aim at a reachable desk and use **Place controls**. Confirm the buttons stay put when you move your head, and select them by pinch and controller. Compare on the same device against the unchanged official demo. If the panel drifts or the table is not detected, start with plane tracking feedback and a reachable floating fallback. Avoid filling the view with virtual scenery.
- Next product pass: add session resume/history and vocabulary review only after the picker and physical interaction pass. Keep any future photo persistence opt-in and make it clear when a generated lesson expires.
